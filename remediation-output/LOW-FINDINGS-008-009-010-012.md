## KP-AUD-008 — CI install scripts download/clone without verification
**Files:** `ci/lint/01_install.sh:28,51,56`; `ci/test/01_base_install.sh:60,83,97`; `ci/test/03_test_script.sh:50,61`.
**Status:** Open — **documented, not changed.** These are inherited Bitcoin-Core CI scripts that run
**only inside Linux CI Docker images** (apt-get, clone into `/usr`, OSX SDK). They **cannot be executed
or verified on this Windows audit host**, and GitHub-hosted Actions for the account are currently held,
so a change here would be untested and could break upstream CI — explicitly to be avoided.
**Recommended fix (for a Linux CI run, verified there):**
- Pin `git clone --depth=1` targets to immutable commit SHAs: pyenv (l.28), llvm-project @`llvmorg-22.1.0`
  (l.60), include-what-you-use @`clang_*` (l.83), bitcoin-core/qa-assets (l.50).
- Add SHA-256 verification for binary downloads: shellcheck (l.51), mlc (l.56), macOS SDK (l.97),
  `script_assets_test.json` (l.61) — compare against a pinned checksum before use.
- Centralize a `verify_download()` helper. Validate on a Linux CI runner (not Windows).

## KP-AUD-012 — lint-files reports 406 missing shebangs
**Status:** **False positive / environment — no repository defect.** Verified: the flagged files DO
contain `#!/usr/bin/env python3`, and **git HEAD stores them as LF** (correct). The 406 failures are
caused by the **Windows working-copy CRLF conversion** (`#!/usr/bin/env python3\r`), which trips
`lint-files.py`'s exact first-line match. On a Linux/LF checkout (i.e. CI) this lint **passes**.
**Correct action:** none in-repo (files are already correct). Optional hardening: add
`* text=auto eol=lf` for `*.py`/`*.sh` in `.gitattributes` to force LF on checkout — deferred to avoid
working-tree renormalization churn during the audit. **Do not "fix" shebangs that are already present.**
